# 要件定義書

## 1. 目的

オンラインの PNG→SVG 変換サービス（例: Convertio）に画像をアップロードせず、手元の PC だけでラスター画像をベクター化（トレース）できるデスクトップアプリを作る。GitHub で公開し、誰でも利用・ビルドできる状態にする。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| トレース | ラスター画像の輪郭を追跡し、SVG の `<path>` に置き換える処理。ラスター画像を `<image>` で埋め込むだけの変換はトレースに含めない |
| プリセット | トレースパラメータの名前付きの組み合わせ |
| 単体変換 | 1 枚の画像をプレビューしながら変換・保存する操作 |
| 一括変換 | 1 つのフォルダ内の対応画像をまとめて変換し、指定フォルダへ保存する操作 |

## 3. スコープ

### 3.1 対象

- ラスター画像（PNG / JPEG / WebP / BMP / GIF）から SVG へのトレース変換
- 単体変換と、フォルダ単位の一括変換
- Windows と Linux 向けのデスクトップアプリ（Tauri 2）
- 日本語と英語の UI
- GitHub Releases でのバイナリ配布

### 3.2 対象外

- PDF の入出力
- AVIF / HEIC / TIFF / SVG などの入力、アニメーション GIF の 2 フレーム目以降
- 写真のトレース品質（変換はできてよいが、品質目標は置かない）
- サブフォルダの再帰的な一括変換
- SVG からラスター画像への変換、SVG の編集機能
- LLM などの生成 AI で SVG を描き直す機能（元画像への忠実さ、結果の再現性、オフライン動作の要件と両立しないため）
- 自動アップデート、コード署名
- macOS、ARM64、モバイル
- CLI 版

## 4. 利用環境

| 項目 | 要件 |
| --- | --- |
| Windows | Windows 10 / 11（x64）。WebView2 ランタイムがない環境ではインストーラーが導入する |
| Linux | x64、WebKitGTK 4.1 が利用できるディストリビューション（Ubuntu 22.04 以降相当） |
| ネットワーク | 不要。アプリは一切通信しない |

## 5. 機能要件

優先度は Must（初回リリースに必須）/ Should（初回リリースに含めたい）で示す。

### FR-01 入力（Must）

- ファイル選択ダイアログとドラッグ&ドロップで画像を指定できる。
- 対応形式は PNG / JPEG / WebP / BMP / GIF。GIF がアニメーションの場合は 1 フレーム目だけを使う。
- 対応拡張子は `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.gif`（大文字小文字を区別しない）。
- 拡張子が対応していても中身をデコードできない場合は、そのファイルをエラーとして扱う。
- 総ピクセル数が上限を超える画像はエラーとして扱う。上限値は詳細設計で定め、名前付き定数にする。
- 透過（アルファチャンネル）を持つ画像では、透過部分を塗りつぶさず、SVG でも透過のままにする。

### FR-02 単体変換（Must）

- 元画像と変換後 SVG を左右に並べてプレビューできる。
- プリセットを選べる。初回リリースのプリセットは次の 3 つ。各プリセットのパラメータ値は詳細設計で定める。
  - ロゴ（カラー）
  - アイコン（少色）
  - 白黒
- 主要パラメータ（カラー/白黒、色の精度、ノイズ除去の強さ、角の判定、曲線/多角形）を UI で調整できる。その他のパラメータは「詳細設定」にまとめる。
- パラメータを変更すると自動で再変換し、プレビューを更新する。連続した変更で変換が溜まらないようにする。
- 変換結果の SVG のファイルサイズとパス数を表示する。
- 保存ダイアログで保存先を選び、SVG を保存できる。初期ファイル名は元画像のファイル名の拡張子を `.svg` に替えたもの。

### FR-03 一括変換（Must）

- 入力フォルダと出力フォルダをダイアログで指定する。両者は同じフォルダでもよい。
- 入力フォルダの直下にある対応拡張子のファイルだけを対象にし、サブフォルダは見ない。対象外のファイルは無視し、その件数を表示する。
- 変換パラメータは、一括変換を開始した時点で選ばれているプリセットと設定を全ファイルに使う。
- 出力ファイル名は元画像のファイル名の拡張子を `.svg` に替えたもの。
- 同名のファイルが出力フォルダにすでにある場合、または同じ一括変換の中で出力名が重なる場合（例: `logo.png` と `logo.jpg`）は、上書きせず `name (1).svg`、`name (2).svg` … と番号を付けて保存する。
- 進捗（完了件数 / 全件数、処理中のファイル名）を表示する。
- キャンセルできる。キャンセル後は新しいファイルの変換を始めない。書き込み途中の不完全な SVG を出力フォルダに残さない。
- 1 ファイルの失敗で一括変換全体を止めない。
- 終了時に、成功・失敗の件数と、失敗したファイルごとの理由を表示する。
- 複数の CPU コアを使って並列に変換する。

### FR-04 多言語対応（Must）

- UI を日本語と英語で表示できる。エラーメッセージも両言語で用意する。
- 初回起動時は OS の言語設定が日本語なら日本語、それ以外なら英語で表示する。
- アプリ内で言語を切り替えられ、次回起動時も切り替えた言語を使う。

### FR-05 ライセンス表示（Must）

- アプリ内の「このアプリについて」画面で、バージョン、本アプリの MIT ライセンス、同梱している第三者ライブラリのライセンス一覧を表示する。

### FR-06 エラー表示（Must）

- 次の場合に、原因が分かるメッセージを表示する: 非対応形式、デコード失敗、画像サイズ超過、読み込み・書き込みの失敗（権限不足、ディスク容量不足など）。
- 単体変換のエラーはアプリを終了させず、別の画像を選び直せる状態に戻る。

### FR-07 設定の保持（Should）

- 最後に使ったプリセットとパラメータ、一括変換の入力・出力フォルダを次回起動時に復元する。

## 6. 非機能要件

### NFR-01 セキュリティ・プライバシー

- アプリは外部と一切通信しない。テレメトリ、自動アップデート確認、外部リソースの読み込みを含めない。Content Security Policy で外部への接続を禁止する。
- Tauri の capabilities は必要最小限にする。ファイルの読み書きは、ユーザーがダイアログまたはドラッグ&ドロップで選んだファイル・フォルダに限る。フロントエンドから任意のパスを読み書きできる経路を作らない。

### NFR-02 性能

- 1024×1024 px のロゴ画像を既定のプリセットで変換したとき、3 秒以内にプレビューが表示される（基準環境は詳細設計で定める）。
- 一括変換の実行中も UI は操作可能で、キャンセル操作は 1 秒以内に受け付けられる。

### NFR-03 変換品質

- 出力 SVG は XML として妥当で、`<image>` 要素を含まない。
- 出力 SVG の `viewBox` と幅・高さは入力画像のピクセルサイズと一致する。
- 出力 SVG をラスター化し元画像と比較したとき、テスト用のロゴ・アイコン画像で一定以上の一致度になる。一致度の算出方法としきい値は詳細設計で定める。

### NFR-04 配布

- GitHub の公開リポジトリで MIT ライセンスとして公開する。
- GitHub Actions で Windows と Linux 向けにビルドし、GitHub Releases に添付する。
  - Windows: MSI と NSIS インストーラー（.exe）
  - Linux: AppImage と .deb
- コード署名は行わない。README に Windows SmartScreen の警告が出ることを記載する。

### NFR-05 ライセンス管理

- 依存ライブラリのライセンスは、MIT / Apache-2.0 / BSD / ISC / Zlib など、MIT ライセンスのアプリにバイナリで同梱できるものに限る。GPL / AGPL のライブラリは使わない。
- 第三者ライセンス一覧はビルド時に自動生成し、手作業で管理しない。
- CI で依存ライブラリのライセンスを検査し、許可リスト外のライセンスが混入したらビルドを失敗させる。

### NFR-06 品質・保守

- Rust の変換処理とフロントエンドのロジックに自動テストを用意し、CI で Windows と Linux の両方で実行する。
- テスト用の画像（フィクスチャ）はリポジトリに含める。
- コーディング規約はリポジトリ内の文書で定め、実装者（人間・AI）が参照できるようにする。

### NFR-07 使いやすさ

- 主要な操作（画像の選択、プリセットの選択、保存、一括変換の開始・キャンセル）はキーボードだけでも行える。

### NFR-08 外観

- ライト / ダークの配色を持ち、OS の設定に従って切り替わる。
- ウィンドウの最小サイズを定め、それ以上のどのサイズでも操作部品が重ならず、横スクロールが発生しない。最小サイズの値は詳細設計で定める。
- 高解像度ディスプレイ（表示倍率 100%〜200%）で文字やアイコンがぼやけない。
- プレビューは拡大縮小と表示位置の移動ができる。元画像と SVG のプレビューは同じ倍率・位置で連動する。
- 透過部分は市松模様の背景で表示し、白い背景と区別できる。

## 7. 受け入れ基準

初回リリースは、次をすべて満たしたときに受け入れる。

1. FR-01〜FR-06 の Must 要件について、詳細設計で定めるテストケースがすべて合格する。
2. 次のフィクスチャで、単体変換と一括変換の結果が NFR-03 を満たす。
   - 透過背景のカラーロゴ（PNG）
   - 白黒アイコン（PNG）
   - 同じロゴの JPEG / WebP / BMP / GIF 版
   - アニメーション GIF（1 フレーム目が使われること）
3. 次の異常系で FR-06 のとおりにエラーが表示され、アプリが操作可能なまま残る。
   - 拡張子は `.png` だが中身が壊れたファイル
   - ピクセル数の上限を超える画像
   - 書き込み権限のない出力フォルダ
4. 一括変換で、出力名が重なるケース（既存ファイルとの重複、`logo.png` と `logo.jpg` の重複）が番号付きの別名で保存される。
5. 一括変換を途中でキャンセルしたとき、出力フォルダに不完全な SVG が残らない。
6. Windows と Linux の両方で、GitHub Actions がビルドしたインストーラーからインストールして起動し、上記 2〜5 を手動で確認できる。
7. アプリの実行中に外部への通信が発生しない。
8. CI のライセンス検査が通り、「このアプリについて」画面に第三者ライセンス一覧が表示される。

## 8. 詳細設計で決めること

- 画面構成と画面遷移
- フロントエンドのフレームワーク
- 各プリセットのパラメータ値
- 画像サイズの上限値
- 変換品質の一致度の算出方法としきい値
- 性能の基準環境
- 設定の保存場所と形式
- Tauri の capabilities とコマンドの一覧（ファイルアクセスをユーザー選択のパスに限る仕組みを含む）
- 使用ライブラリとバージョン
