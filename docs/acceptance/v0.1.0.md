# v0.1.0 受け入れ確認の結果（T14）

要件 §7 の受け入れ基準を、[manual-test.md](../manual-test.md) に沿って確認した結果。

## 対象と環境

| 項目 | 内容 |
| --- | --- |
| 公開するビルド | タグ `v0.1.0`（`205f567`）。Release ワークフローの成果物 4 種類 |
| Windows | Windows 11 Home（ビルド 26300）、WebView2 ランタイム 154.0.4258.37。確認者: オーナー |
| Linux | Ubuntu 24.04.5 LTS（WSLg）、WebKitGTK 4.1（2.52.6）。画面の操作はオーナー、出力と通信の検査は Opus |

基準 2〜6 と 8 は、`2987020`（PR #22 のマージ）のビルドで確認した。その後の PR #23（Windows の WebView2 の起動オプション）と PR #24（単体変換のエラーの帯の配置）は変換・保存・一括変換の処理を変えていないので、`205f567` では変更に関わる基準 7 とエラー表示だけを確認し直した。

### 基準 7 の詳細

- Linux: 本体と WebKitGTK の子プロセスを `strace -f` で約 14 分記録し、インターネット用のソケット（AF_INET / AF_INET6）は作られなかった。
- Windows: `scripts/watch-network.ps1` で、本体とそこから起動された WebView2 のプロセスを記録した。`205f567` での接続は、起動直後の `substrate.office.com`:443 の 2 本だけ。要件 NFR-01 の例外（WebView2 ランタイム自身の通信）にあたり、README に明記している。
- `2987020` では、これに加えてシステムのプロキシ設定の自動構成スクリプト（PAC）の取得と、起動の約 60 秒後の Microsoft への接続があった。PR #23 の起動オプションで止まったことを `205f567` で確かめた。

## 確認中に見つけて直したこと

| 内容 | 対応 |
| --- | --- |
| Windows の WebView2 が、プロキシ設定の PAC と Microsoft のサーバーに接続していた | PR #23。止められない `substrate.office.com` は要件の例外とした |
| 壊れた画像を開くと、単体変換のツールバーとプレビューがエラーの帯の高さ分、下・上・下と動いた | PR #24。`205f567` で、Windows で動かないことを目視で確認 |
| AppImage が Ubuntu 24.04 で起動しない（FUSE 2 がない） | PR #23 で README に `libfuse2t64` / `libfuse2` のインストールを追記。.deb は影響なし |
| 手順書の `icacls … (W)` がフォルダを開くことまで拒否していた | PR #23 で `(WD,AD)` に修正 |
| MSI と NSIS が同じフォルダにインストールされ、両方を入れると片方のアンインストールでもう一方のファイルも消える | README に、どちらか一方だけを使うよう追記 |

## 未確認の事項

- AppImage は、FUSE 2 を入れた状態での起動を確かめていない。確認は `APPIMAGE_EXTRACT_AND_RUN=1` で展開して起動する方法で行った。
