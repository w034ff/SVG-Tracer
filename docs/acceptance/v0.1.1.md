# v0.1.1 の確認結果

v0.1.0 からの変更点を、タグ `v0.1.1`（`fe0f137`）の Release ワークフローの成果物で確認した結果。変換・保存・一括変換の処理と WebView2 の設定は変えていないので、[v0.1.0 の受け入れ確認](v0.1.0.md)の基準 2〜8 はやり直していない。

| 確認項目 | Windows（NSIS） | Linux（AppImage） |
| --- | --- | --- |
| プリセット「イラスト（色数少なめ）」、詳細設定「線分の最小長」、バージョン 0.1.1 の表示 | 合格 | 合格 |
| 壊れたファイルと上限超過のエラー文言（設計 §5.5 の表のとおり、上限は 16,777,216） | 合格 | 合格 |
| 一括変換の後に出力フォルダを選び直すと、全行が「待機」に戻る | 合格 | 合格 |
| 英語表示（プリセット名、一括変換の件数の文言） | 合格 | 未確認 |
| v0.1.0 からの上書きインストール | 合格（自動インストール） | — |
| FUSE 2（`libfuse2t64`）を入れた状態で AppImage を展開せずに起動 | — | 合格 |

## フォントについて

`--font-sans` に `Noto Sans CJK JP` を足したが、確認に使った Linux（Takao フォントの fontconfig 設定あり）では、追加の前後で使われるフォントは変わらなかった（WebKitGTK で同じ文字列の幅を比べて判定）。理由は設計 §8.5 に書いた。表示の不具合はない。
