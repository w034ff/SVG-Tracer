## テスト項目

### 2. フィクスチャ画像の単体変換・一括変換と SVG 品質確認（要件 §7-2, NFR-03）

各形式のフィクスチャ画像を単体変換および一括変換し、出力された SVG の品質要件を満たしているか確認します。

#### 手順

##### 2.1 単体変換の確認
1. アプリを起動し、「単体変換」タブを表示する。
2. 「画像を開く」ダイアログまたはドラッグ＆ドロップで、以下のフィクスチャを 1 つずつ読み込む:
   - `logo_color.png`
   - `icon_mono.png`
   - `logo_color.jpg`
   - `logo_color.webp`
   - `logo_color.bmp`
   - `logo_color.gif`
   - `anim.gif`
3. プレビュー画面で左右（元画像と SVG）の同期ズーム・移動、市松模様の透過表示、パス数・ファイルサイズ・変換時間の表示を確認する。
4. プリセットを切り替えてプレビューが更新されることを確認する（例: `logo_color.png` では「ロゴ（カラー）」、`icon_mono.png` では「白黒」）。
5. 「SVG を保存」ボタンを押し、任意のフォルダに SVG を保存する。

##### 2.2 一括変換の確認
1. テスト用の入力フォルダを作成し、上記フィクスチャ（`logo_color.png` / `.jpg` / `.webp` / `.bmp` / `.gif`、`icon_mono.png`、`anim.gif`）をすべてコピーして配置する。
2. 「一括変換」タブを開く。
3. 「入力フォルダ」の「フォルダを選択」を押して作成したフォルダを指定する。対象ファイル数（7件）が表示されることを確認する。
4. 「出力フォルダ」の「フォルダを選択」を押して空の出力フォルダを指定する。
5. 「変換を開始」をクリックする。進捗バーが進み、全件成功して集計が表示されることを確認する。

##### 2.3 出力 SVG の検査
保存された各 SVG ファイルをテキストエディタおよびブラウザで開き、以下を検証する:
1. **`<image>` 要素の不在**: テキストエディタまたは grep コマンド等で `<image` を検索し、一切含まれていないことを確認する。
   ```bash
   grep -in "<image" output/*.svg
   ```
2. **寸法の一致**: SVG のルート要素の `width` と `height`、および `viewBox` の幅・高さが元画像のピクセルサイズと一致していることを確認する。
   - `logo_color.*`: `width="1024" height="1024"`、`viewBox` の幅 1024、高さ 1024
   - `icon_mono.png`: `width="256" height="256"`、`viewBox` の幅 256、高さ 256
   - `anim.gif`: `width="128" height="128"`、`viewBox` の幅 128、高さ 128
   - （※透過余白が付与されたカラー画像の場合、`viewBox="1 1 1024 1024"` のようになります）
3. **視覚的一致**: ブラウザで SVG を開き、元画像と比較して著しい歪みや欠損、透過部分の塗りつぶれがないこと。
4. **アニメーション GIF の 1 フレーム目採用**: `anim.gif` から生成された SVG が、1 フレーム目の色・図形になっていること。

#### 期待する結果
- すべての形式が正常に変換できること。
- 出力 SVG が XML として妥当であり、`<image>` 要素を含まないこと。
- `width`・`height`・`viewBox` の寸法が元画像のピクセルサイズと合致していること。
- 元画像と大きく乖離しないベクター画像が生成されていること。
- `anim.gif` で 1 フレーム目が採用されていること。

### 3. 異常系でのエラー表示とアプリの操作性維持（要件 §7-3, FR-06）

異常な入力や環境において、アプリがクラッシュせず分かりやすいエラーを表示し、操作可能な状態を維持することを確認します。

#### 手順

##### 3.1 壊れたファイル（デコード失敗）
1. 「単体変換」タブで `crates/tracer/tests/fixtures/corrupt.png` を開く（またはドロップする）。
2. エラーメッセージが表示されることを確認する。
3. エラー表示後もアプリがクラッシュせず、別の画像を選び直せることを確認する。
4. 「一括変換」タブの「入力フォルダ」の「フォルダを選択」を押して `corrupt.png` を含むフォルダを指定して実行し、他の正常なファイルは変換され、`corrupt.png` のみ失敗として理由が表示されることを確認する。

##### 3.2 ピクセル数上限（16,777,216 px）超過画像
上限を超える画像はリポジトリに含まれていないため、生成プログラムを実行してテスト用画像を作成します。

1. **上限超過画像の生成**:
   リポジトリルートで以下のコマンドを実行し、上限（16,777,216 ピクセル）を超える 4097×4097（16,785,409 ピクセル）の PNG 画像を生成する（`gen_oversized` は `tracer::MAX_PIXELS` から動的に辺の長さを算出します）。
   ```bash
   # Linux / macOS
   cargo run -p tracer --example gen_oversized -- /tmp/oversized.png

   # Windows (PowerShell)
   cargo run -p tracer --example gen_oversized -- C:\temp\oversized.png
   ```
2. 「単体変換」タブで生成した画像を開く。
3. 画像サイズ上限超過のエラーメッセージが表示されることを確認する。
4. アプリがクラッシュせず、別の正常な画像を選び直して変換できることを確認する。

##### 3.3 書き込み権限のない出力フォルダ

1. **書き込み権限のないフォルダの作成**:
   - **Linux**:
     ```bash
     mkdir -p /tmp/no_write_perm
     chmod 555 /tmp/no_write_perm
     ```
   - **Windows (PowerShell)**:
     ```powershell
     New-Item -ItemType Directory -Path "C:\temp\no_write_perm" -Force
     icacls "C:\temp\no_write_perm" /deny '*S-1-1-0:(W)'
     ```
2. 「一括変換」タブで、「出力フォルダ」の「フォルダを選択」を押して上記で作成したフォルダを指定する。
3. 任意の正常な画像を含む入力フォルダを指定し、「変換を開始」を実行する。
4. 書き込み失敗（権限不足等）のエラーが表示され、アプリが異常終了しないことを確認する。
5. **テスト後のクリーンアップ**:
   - Linux: `chmod 755 /tmp/no_write_perm && rm -rf /tmp/no_write_perm`
   - Windows: `icacls "C:\temp\no_write_perm" /remove:d '*S-1-1-0'` 実行後にフォルダ削除。

#### 期待する結果
- いずれの異常系でもアプリが強制終了（クラッシュ）しないこと。
- ユーザーに原因が伝わる適切なエラーメッセージが表示されること。
- エラー後も別の操作や再選択が可能であること。

#### 結果
- [ ] 合格 / [ ] 不合格

### 4. 一括変換での出力名重複の解決（要件 §7-4, FR-03）

既存の出力ファイルや同名・異拡張子の入力ファイルが存在する場合に、上書きせず連番（`name (1).svg`）が付与されて保存されることを確認します。

#### 手順

##### 4.1 出力フォルダに同名ファイルが既存の場合
1. 空の出力フォルダに、あらかじめダミーの `logo_color.svg` を配置しておく。
2. 入力フォルダに `logo_color.png` を配置する。
3. 「一括変換」タブで「変換を開始」を実行する。
4. 出力フォルダを確認する。

##### 4.2 入力フォルダ内で出力名が重複する場合
1. 新たな空の入力フォルダを作成し、同一のベース名を持つ異形式のファイル（例: `logo.png` と `logo.jpg`）を配置する。
   （※フィクスチャの `logo_color.png` をコピーして `logo.png`、`logo_color.jpg` をコピーして `logo.jpg` とする）
2. 空の出力フォルダを指定して「変換を開始」を実行する。
3. 出力フォルダを確認する。

#### 期待する結果
- 4.1: 既存の `logo_color.svg` は上書きされず、新しく `logo_color (1).svg` として保存されること。
- 4.2: 一方が `logo.svg`、他方が `logo (1).svg` として保存され、両方とも正常に出力されること。

### 5. 一括変換のキャンセル処理（要件 §7-5, FR-03, NFR-02）

変換途中でキャンセルした際に、処理が速やかに停止し、不完全な一時ファイルが残らないことを確認します。

#### 手順
1. 入力フォルダに多数の画像ファイル（フィクスチャの画像を複数回コピーして 20〜30 個程度配置）を用意する。
2. 空の出力フォルダを指定して「変換を開始」をクリックする。
3. 変換処理中に「キャンセル」ボタンをクリックする。
4. キャンセル受付時間とステータス表示を確認する。
5. 出力フォルダの中身を確認する。一時ファイルは `tempfile` クレートの既定名 `.tmpXXXXXX`（Linux ではドットから始まる隠しファイル）として出力フォルダ内に作成されたのちリネームされるため、隠しファイルも含めて確認する:
   - **Linux**: `ls -A /path/to/output`
   - **Windows**: `dir /a "C:\path\to\output"`

#### 期待する結果
- キャンセルボタン押下後、1 秒以内に「キャンセル中…」へ遷移し、追加のファイル変換が直ちに停止すること。
- キャンセル完了時点で成功したファイルはそのまま残り、書き込み途中の不完全なファイル（一時ファイル `.tmpXXXXXX` や空のファイル等）が出力フォルダに残っていないこと。

### 6. インストーラーからのインストールと起動（要件 §7-6）

GitHub Actions の Release ワークフローでビルドされたインストーラー・パッケージを用いてインストールおよび起動を確認します。

#### 手順

##### Windows (MSI / NSIS)
1. GitHub Releases（下書き）から `.msi` または `.exe`（NSIS）をダウンロードする。
2. インストーラーを実行する。
   - Windows Defender SmartScreen の警告（「Windows によって PC が保護されました」）が表示されたら、「**詳細情報**」をクリックし、「**実行**」ボタンを押して継続する。
3. WebView2 ランタイムが未インストールの環境の場合、インストーラーにより WebView2 のセットアップが行われることを確認する。
4. インストールを完了し、スタートメニューまたはショートカットからアプリ（`SVG Tracer`）を起動する。

##### Linux (AppImage / .deb)
- **AppImage**:
  1. GitHub Releases から `SVG*Tracer_*_amd64.AppImage` をダウンロードする。
  2. ターミナルで実行権限を付与して実行する:
     ```bash
     chmod +x SVG*Tracer_*_amd64.AppImage
     ./SVG*Tracer_*_amd64.AppImage
     ```
- **.deb パッケージ**:
  1. GitHub Releases から `./SVG*Tracer_*_amd64.deb` をダウンロードする。
  2. `apt` を使ってインストールする:
     ```bash
     sudo apt install ./SVG*Tracer_*_amd64.deb
     ```
  3. アプリケーションメニューまたはターミナルから `svg-tracer` を実行する。

#### 期待する結果
- エラーなくインストールが完了し、アプリのウィンドウ（既定サイズ 1200×800）が正常に起動すること。
- UI の言語が OS の言語設定（日本語環境なら日本語、それ以外なら英語）に従って初期表示されること。
- 基準 2〜5 の各項目がこのインストール済み環境で正常に実行・確認できること。

### 7. 外部通信の非発生確認（要件 §7-7, NFR-01）

アプリの起動中および操作中に、意図しない外部ネットワーク通信が一切発生しないことを確認します。

#### 手順

##### Windows での確認手順
1. リソース モニター（`resmon.exe`）を起動し、「ネットワーク」タブを開く（または Sysinternals の TCPView を起動する）。
2. 「ネットワーク活動のプロセス」一覧を開く。
3. 以下の 2 種類のプロセスを特定し、チェックボックスをオンにして活動を監視する:
   - アプリ本体プロセス: `svg-tracer.exe`
   - WebView2 関連プロセス: `msedgewebview2.exe`
4. アプリ内で以下の各操作を実施する:
   - アプリの起動
   - 「単体変換」タブでの画像読み込み・変換・保存
   - 「一括変換」タブでの変換実行・キャンセル
   - タブの切り替え、パラメータ変更
   - 言語切り替え（日本語 ⇔ 英語）
   - 「このアプリについて」ダイアログの表示
5. リソース モニターの「ネットワーク活動」および「TCP 接続」テーブルを観察し、各プロセスの通信履歴を記録する。
   - ※注意: `svg-tracer.exe` 自体は外部通信を一切行いません。WebView2（`msedgewebview2.exe`）は Microsoft Edge のコンポーネントであるため、OS やランタイムの仕様により Microsoft のサーバ（SmartScreen 判定や利用状況確認等）とバックグラウンド通信を行う可能性があります。観測された通信先 IP アドレス、ホスト名、ポート番号を詳細に記録してください（T14 で結果を評価します）。

##### Linux での確認手順
1. ターミナルで `ss` コマンドによりソケット状態を監視するか、`strace` を用いてネットワーク関連のシステムコールを監視しながらアプリを起動する:
   ```bash
   # 方法 A: strace でフォークされた子プロセスも含めてネットワーク系システムコールをトレース（-f で子プロセスも追跡）
   strace -f -e trace=network ./SVG*Tracer_*_amd64.AppImage 2>&1 | grep -E "connect\(|sendto|recvfrom"

   # 方法 B: 実行中に別ターミナルでソケットを監視（本体プロセスおよび WebKitGTK 子プロセス WebKitNetworkProcess / WebKitWebProcess を監視）
   watch -n 1 'ss -tupa | grep -iE "svg-tracer|WebKit"'
   ```
2. Windows と同様に、アプリ起動、単体変換、一括変換、言語切り替え、「このアプリについて」表示などの各操作を行う。
3. 外部へのアウトバウンド接続（HTTP / HTTPS / DNS 等）が要求されていないことを確認する（※ローカル IPC や X11 / Wayland 用の UNIX ドメインソケット通信は除外）。また、WebKitGTK の子プロセス（`WebKitNetworkProcess`、`WebKitWebProcess`）のソケット・通信状況も監視・記録する。

#### 期待する結果
- アプリ本体（`svg-tracer` / `svg-tracer.exe`）から外部インターネットへの接続・通信が一切発生しないこと。
- Windows の `msedgewebview2.exe`、および Linux の WebKitGTK 子プロセス（`WebKitNetworkProcess`、`WebKitWebProcess`）について通信状況を監視・記録すること。

### 8. ライセンス検査と第三者ライセンス表示（要件 §7-8, FR-05, NFR-05）
